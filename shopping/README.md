# סל — רשימת הקניות שלי

מערכת בעברית, מותאמת לנייד ולמחשב, עם הרשמה בשם משתמש וסיסמה, רשימה פרטית ושמירה ב־SQLite על השרת.

## מה כלול

- הוספה, עריכה, הסרה וסימון מוצרים שנקנו.
- כמויות, יחידות והערות לכל מוצר.
- קטגוריות מובנות והוספה, שינוי שם ומחיקה של קטגוריות ריקות.
- חיפוש וסינון לפי קטגוריה ומצב, מעקב התקדמות ומחיקה מרוכזת של מה שנקנה.
- רענון אוטומטי כל 30 שניות וכשחוזרים לחלון, לשימוש מאותו חשבון במכשירים שונים.
- לוגו, עיצוב RTL, תמיכה במקלדת ותוויות נגישות.

## מצב הפרסום

הקוד מוכן להרצה. GitHub Pages לא מריץ את שרת Node.js ואת מסד הנתונים. יש להריץ את תיקיית `shopping` כיישום שרת; אין לפתוח את `public/index.html` כקובץ או לפרסם אותו לבדו ולצפות להתחברות עובדת. האתר הקיים בשורש המאגר נשאר נפרד.

## הפעלה במחשב עם Docker Desktop

לאחר הורדת המאגר, פותחים מסוף בתיקיית `shopping`:

```sh
docker compose up --build -d
```

פותחים http://localhost:3000, בוחרים ״חשבון חדש״ ונרשמים. הנתונים נשמרים ב־volume בשם `shopping-data`, גם לאחר הפעלה מחדש של המכולה. אין להריץ `docker compose down -v` — הפקודה מוחקת את מסד הנתונים. המחשב צריך להיות פועל כדי שהשרת יהיה זמין.

## הפעלה עם Node.js

נדרשת Node.js 24 ומעלה. אין חבילות חיצוניות להתקין.

```sh
npm start
```

פותחים http://localhost:3000. מסד הנתונים נוצר אוטומטית ב־`shopping/data/shopping.sqlite`. לסביבה מותאמת מעתיקים `.env.example` ל־`.env` ומריצים `node --env-file=.env server.mjs`.

## העלאה לשרת לשימוש מהטלפון ומכל מקום

יש לבחור שירות שמריץ Docker או Node.js ותומך בדיסק קבוע. להגדיר:

| הגדרה | ערך |
|---|---|
| תיקיית היישום | `shopping` |
| פקודת הפעלה | `npm start` |
| גרסת Node.js | 24 ומעלה |
| `NODE_ENV` | `production` |
| `APP_ORIGIN` | כתובת האתר המדויקת ב־HTTPS, ללא `/` בסוף |
| `HOST` | `0.0.0.0` במכולה או לפי הנחיות שירות האירוח |
| `PORT` | הפורט שהאירוח מגדיר, ברירת מחדל 3000 |
| `DB_PATH` | נתיב לקובץ SQLite בתוך הדיסק הקבוע |

השרת חייב להיות מאחורי HTTPS, עם כתובת זהה ל־`APP_ORIGIN`. יש להפעיל מופע שרת אחד על דיסק קבוע; SQLite מקומי אינו מסד נתונים משותף למספר שרתים. אין להסתמך על אחסון זמני או לפרסם לשירות סטטי. מחיר האירוח תלוי בספק ואין בתיקייה פעולה שמרכישה שירות או יוצרת חיוב.

## התחברות והגנות

סיסמאות באורך 10–128 תווים נשמרות בגיבוב scrypt עם salt אקראי. מזהה ההתחברות נשלח ב־HttpOnly cookie, עם SameSite=Strict ו־Secure בייצור; תוקפו 7 ימים. רק גיבוב המזהה נשמר במסד הנתונים. יציאה מבטלת אותו בשרת. כל פעולת קריאה וכתיבה קשורה למשתמש המחובר ונבדקת בשרת. כל בקשת שינוי מחייבת JSON ו־Origin תואם. שאילתות משתמשות בפרמטרים. אין סיסמאות, חשבונות ברירת מחדל או מפתחות בקוד.

יש הגבלת ניסיונות התחברות לפי שם משתמש וכתובת חיבור, שנשמרת במסד הנתונים. שרת מאחורי proxy סופר את כתובת ה־proxy במשותף (40 ניסיונות ב־15 דקות); לשימוש מעבר לקבוצה קטנה יש להוסיף הגבלה בשכבת האירוח ולהתאים טיפול בכתובת לקוח רק דרך proxy מהימן. אין כרגע שחזור סיסמה בדוא״ל, אימות דו־שלבי, או שיתוף רשימות בין חשבונות שונים. באותו חשבון אפשר להתחבר ממספר מכשירים. כאשר שני מכשירים עורכים אותו מוצר, השמירה האחרונה קובעת.

המאגר ציבורי; נתוני המשתמשים נוצרים רק בזמן הריצה, מוחרגים מ־Git ואינם מוגשים כקבצים. אין להעלות תיקיית `data`, קובצי `.env` או גיבויים למאגר.

## גיבוי ושחזור

באירוח יש להפעיל גיבויים של הדיסק הקבוע. בגיבוי ידני: לעצור את השרת, לגבות את כל תיקיית הנתונים למיקום פרטי, ולהפעיל אותו מחדש. בשחזור יש לעצור את השרת, לשחזר את תיקיית הנתונים ולהחזיר את הרשאות המשתמש שמריץ את השרת. מומלץ לבדוק שחזור בפועל. שמירה במסד נתונים אינה תחליף לגיבוי.

## בדיקות
